# 모션 인식 게임 – 웹캠 포즈·손 인식으로 조작하는 Unity 게임

> 팀 프로젝트 (2023.03 ~ 2023.12)
> 웹캠 하나로 사람의 몸과 손 동작을 인식해, 컨트롤러 없이 몸으로 플레이하는 "오즈의 마법사" 테마 스테이지형 게임

| 항목 | 내용 |
|---|---|
| 형태 | 팀 프로젝트. 팀원이 스테이지를 하나씩 맡아 개발하고 하나의 게임으로 연결 |
| 본인 담당 | 동작 인식·통신 공통부, **장애물 회피 스테이지**, **아이템 전달 스테이지** |
| 기술 | Python, OpenCV, cvzone(MediaPipe 기반 Hand·Pose 인식), UDP 소켓, Unity 2020.3, C# |
| 원본 저장소 | `CD-MotionCap/MotionGameProject` (팀 조직 저장소) |
| 공개 범위 | 본인이 작성한 스크립트만 포함. 팀원 코드, 3D 에셋, 씬 파일은 제외 |

---

## 1. 동작 구조

```
 [웹캠] ──▶ handbody.py (Python)
            ├ PoseDetector : 몸 랜드마크 33개
            ├ HandDetector : 손 랜드마크 21개
            └ UDP 전송 (127.0.0.1:5052)
                 "[x0, y0, z0, x1, y1, z1, ...]"   ← 몸 33개 → 손 21개 순서
                          │
                          ▼
 [Unity] UDPReceive.cs ── 백그라운드 스레드에서 수신
            ├ Minho_PoseTracking : 몸 좌표 → 3D 관절 오브젝트
            ├ Minho_HandTracking : 손 좌표 → 3D 손가락 오브젝트
            └ 스테이지별 게임 로직 (장애물 회피 / 아이템 전달)
```

- Python은 이미지 좌표의 y축(아래로 증가)을 `h - y`로 뒤집어 보내서, Unity에서는 값이 클수록 위쪽이 되도록 맞췄습니다.
- Unity는 문자열을 `,`로 나눈 뒤, 몸 랜드마크는 `i * 3`, 손 랜드마크는 `(i + 33) * 3` 위치에서 읽습니다.
- UDP 수신은 별도 스레드에서 처리해, 데이터를 기다리는 동안 게임 화면이 멈추지 않게 했습니다.

## 2. 담당 스테이지

### 2-1. 장애물 회피 게임 (`ObstacleGame/`)
달려오는 장애물을 몸 동작으로 피하는 스테이지입니다.

| 동작 | 판정 기준 (몸 랜드마크 y좌표) | 결과 |
|---|---|---|
| 두 손을 입보다 높이 들기 | 양손 검지(19, 20)가 입(9)보다 위 + 캐릭터가 땅에 닿아 있음 | 점프 |
| 왼팔을 어깨 높이로 뻗기 | 왼쪽 팔꿈치(13)·손목(15)이 왼쪽 어깨(11)와 ±40px 이내 | 왼쪽 이동 |
| 오른팔을 어깨 높이로 뻗기 | 오른쪽 팔꿈치(14)·손목(16)이 오른쪽 어깨(12)와 ±40px 이내 | 오른쪽 이동 |

- **점프 중복 방지**: 캐릭터 아래로 Raycast를 쏴서 땅에 닿아 있을 때만 점프가 되도록 했습니다(`CheckGround`).
- **장애물 생성** (`EnemySpawner`): 설명 화면이 끝난 뒤 1.5초 간격으로 장애물을 무작위 생성합니다. 장애물 종류에 따라 좌·우 레인 중 한 곳에 나오거나, 가운데 바닥에 나와 점프로 넘어야 합니다.
- **게임 규칙** (`Manager`):
  - HP 5로 시작하고, 장애물에 부딪힐 때마다 1씩 줄면서 캐릭터가 깜빡입니다.
  - 40초를 버티면 성공 화면 뒤 다음 스테이지(`6to7`)로 넘어갑니다.
  - HP가 0이 되면 게임오버 화면을 보여 주고 5초 뒤 다시 시작합니다.
- **배경 반복** (`GuideMove`): 바닥 오브젝트가 일정 위치를 지나면 뒤로 되돌려, 길이 끝없이 이어지는 것처럼 보이게 했습니다.
- **동작 안내**: 인식된 동작마다 "점프·왼쪽·오른쪽·충돌" 안내 패널을 1초간 띄워, 플레이어가 자신의 동작이 인식됐는지 바로 알 수 있게 했습니다.

### 2-2. 아이템 전달 게임 (`ItemGame/`)
손으로 아이템을 집어, 그 아이템이 필요한 캐릭터에게 전달하는 스테이지입니다.

| 아이템 | 정답 캐릭터 |
|---|---|
| 심장 | 양철 나무꾼 |
| 뇌 | 허수아비 |
| 물약(용기) | 사자 |

- **집기 판정** (`Minho_ChangeColor`): 지정한 두 손가락 끝 오브젝트 사이 거리가 0.5 미만이면 "집은 상태"로 판단하고, 아이템이 검지 끝(손 랜드마크 8번)을 따라 움직입니다. 손가락을 벌리면 아이템을 놓습니다.
- **아이템 구분** (`TriggerCheck`): 손이 닿은 아이템의 태그(Heart·Brain·Potion)로 지금 어떤 아이템을 들고 있는지 기록합니다.
- **정답 판정** (`CheckHeart`): 아이템을 캐릭터에 가져가면, 맞는 캐릭터는 초록색, 틀린 캐릭터는 빨간색으로 바뀝니다.
- **클리어** (`GameClear`): 정답을 맞춘 아이템은 캐릭터 앞 정해진 위치에 고정됩니다. 세 개를 모두 맞추면 클리어 화면 뒤 다음 스테이지(`7to8`)로 넘어갑니다.

## 3. 폴더 구조

```
motion-game/
├── python/
│   └── handbody.py                 # 웹캠 손·몸 인식 → UDP 전송
└── unity/Scripts/
    ├── Common/
    │   ├── UDPReceive.cs           # UDP 수신 (백그라운드 스레드)
    │   ├── Minho_PoseTracking.cs   # 몸 랜드마크 33개 → 관절 오브젝트
    │   └── Minho_HandTracking.cs   # 손 랜드마크 21개 → 손가락 오브젝트, 검지 끝 좌표
    ├── ObstacleGame/
    │   ├── Minho_PlayerMove.cs     # 동작 판정(점프·좌우), 충돌·HP
    │   ├── Manager.cs              # 타이머, 성공·게임오버, 씬 전환
    │   ├── EnemySpawner.cs         # 장애물 무작위 생성
    │   ├── Enemy.cs                # 장애물 이동·제거
    │   └── GuideMove.cs            # 바닥 반복 이동
    └── ItemGame/
        ├── Minho_ChangeColor.cs    # 집기 판정, 아이템 손가락 추적
        ├── TriggerCheck.cs         # 들고 있는 아이템 구분
        ├── CheckHeart.cs           # 캐릭터별 정답·오답 판정
        └── GameClear.cs            # 클리어 조건, 다음 스테이지 전환
```

- 원본 스크립트의 한글 주석이 CP949로 저장되어 있어, GitHub에서 읽을 수 있도록 UTF-8로 변환했습니다. 코드 내용은 바꾸지 않았습니다.
- 씬·프리팹·3D 에셋은 원본 Unity 프로젝트에 있어, 이 폴더만으로는 게임을 실행할 수 없습니다.

## 4. 실행 흐름 (원본 프로젝트 기준)
1. `pip install opencv-python cvzone mediapipe` 후 `python handbody.py`를 실행해 웹캠 인식을 시작합니다.
2. Unity 2020.3.38f1에서 프로젝트를 열고 씬을 재생하면, `UDPReceive`가 5052 포트로 좌표를 받아 캐릭터를 움직입니다.
